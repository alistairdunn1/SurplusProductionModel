### Bug Fixes in Model Fitting (Session 3)
Multiple bugs discovered and fixed when testing with the ross_sea datasets:

1. **NA-safety in objective function** (`R/rtmb-objective.R`)
   - `any(B <= 0.01)` failed when B contained NaN from extreme parameter combos
   - Added `!is.finite()` guards on all boundary checks
   - Added `production[!is.finite(production)] <- 0` guard
   - Added final `if (!is.finite(nll)) nll <- 1e8` fallback

2. **Catch matrix dimensionality** (`R/model-fitting.R`)
   - `catch_mat[t, ]` failed when catch was a vector (single-area)
   - Fixed with `is.matrix()` check before subscripting

3. **Column access with `$` operator** (`R/model-fitting.R`)
   - `data.frame$column` inside package namespace failed with custom attributes
   - Replaced all `$` column accessors with `[[` in `preprocess_model_data`
   - Added `as.data.frame()` coercion at function entry

4. **CPUE filter producing zero rows** (`R/model-fitting.R`)
   - `NULL %in% NULL` evaluates to `logical(0)`, collapsing to zero rows
   - Fixed with explicit `if (has_label)` guard before label filtering

5. **Year alignment dropping catch years** (`R/model-fitting.R`)
   - `preprocess_model_data` used `intersect(cpue_years, catch_years)`
   - This dropped years where catch existed but CPUE didn't (e.g. first year)
   - Fixed to use `union()` — model now includes all years with catch or CPUE
   - CPUE for missing years is NA, handled correctly by the likelihood

6. **K starting value heuristic too low** (`R/rtmb-objective.R`)
   - `avg_catch * 10` gave far too low K for slow-growing species
   - Replaced with MSY-based heuristic: geometric mean of `4*max_catch/r` and `avg_catch*30`

## 🔧 TECHNICAL NOTES

### Architecture
- S3 class system (named list with `class = "ProductionModel"`)
- `validate_ProductionModel()` exported for post-hoc validation
- Log-transformed parameters for positivity constraints
- Modular design: objective function, fitting, reference points, diagnostics
- MVP uses `nlminb` with finite-difference gradients; RTMB AD planned

### Known Limitations
- **Parameter identifiability**: Surplus production models have ridge-like likelihood surfaces. The shape parameter *m* and initial biomass *B*~0~ are poorly identified from CPUE alone. Standard practice is to fix *m* (e.g. Schaefer: *m* = 2).
- **Convergence sensitivity**: Auto-generated starting values sometimes fail to converge. Providing informed starting values and using `fixed_params` greatly improves reliability.

### RTMB Technical Constraints Discovered
Key insights from debugging RTMB's complex-step AD in closures:

1. **Advector containers required**: `numeric(n)[i] <- advector_val` in closures silently strips the advector class to complex. Must pre-allocate with `RTMB::advector(numeric(n))`.
2. **No branching on AD types**: `if (x < val)` fails for advector values. Use differentiable soft bounds instead.
3. **Explicit RTMB::dnorm**: `stats::dnorm` doesn't handle advectors — must use `RTMB::dnorm()` explicitly.
4. **ADREPORT ≠ REPORT**: `ADREPORT()` values come via `sdreport()`, NOT `obj$report()`. Separate `REPORT()` calls needed for `obj$report()` extraction.
5. **Advector NaN initialization**: `RTMB::advector(numeric(n))` initializes with NaN real parts (complex type). `Re()` returns NaN. Plain `numeric()` containers work for REPORT but lose AD tracking.
6. **Results via plain R**: Most robust approach is to extract fitted parameters and recompute derived quantities in plain R (via `calculate_model_results()`), keeping ADREPORT only for delta-method SEs.
7. **Parameter name collisions**: `unlist()` on named list elements concatenates inner+outer names. Strip inner names before `unlist()` to avoid doubled suffixes.
